# 智能温控手环（Smart Wristband Thermostat）

用手腕皮肤温度**闭环控制空调**的物联网原型。

市场上所有空调遥控器都只有一个数字——设定温度，它假设"26℃ 对所有人都舒适"。而空调真正控制的是**房间**，不是**人**。这个项目把人体的温度信号接进控制回路，让空调第一次知道坐在它下面的人此刻是冷是热。

> 从"控室温"，变成"控人体热舒适"。

---

## 系统架构

```
┌──────────────────┐   ESP-NOW 上行 1Hz    ┌──────────────────┐   红外 38kHz   ┌────────┐
│ 腕端 ESP32-S3     │ ────────────────────► │ 中枢 ESP32-C3     │ ─────────────► │ 奥克斯  │
│ · M601 皮温 1Hz   │   皮温 / seq / CRC     │ · DHT11 室温湿度   │  104bit 帧     │ 空调    │
│ · 240×280 显示    │ ◄──────────────────── │ · 决策 + 红外发射  │                └────────┘
│ · 状态灯          │   ESP-NOW 下行 1Hz    │ · 对外 API         │
└──────────────────┘   室温/湿度/空调/时间  └──────────────────┘
```

两个节点**点对点直连**，不依赖路由器、不依赖云、断网可用，数据不出户。

## 硬件

| 部件 | 型号 | 说明 |
|---|---|---|
| 腕端主控 | 微雪 ESP32-S3-Touch-LCD-1.69 | 16MB Flash / 8MB PSRAM，1.69" 240×280 ST7789 |
| 皮温传感器 | 敏源 M601 | 1-Wire，±0.1℃ 级。**注意：公式是 T = 40 + raw/256，不是 DS18B20 那套** |
| 中枢主控 | ESP32-C3 | USB 口是 WCH 桥接芯片，`CDCOnBoot` 必须 default |
| 室温湿度 | DHT11（待换 SHT30） | ±2℃，靠软件校准补偿 |
| 红外发射 | 发射模块 + 发射管 | **VCC 必须 5V**，3.3V 射程不足 1 米 |
| 被控对象 | 奥克斯空调 | 13 字节 / 104bit，NEC 风格时序，LSB first |

## 快速开始

```bash
source env.sh

# 编译 / 烧录
build   _wb          # 腕端
buildc3 _c3_hub      # 中枢

flashc3 _c3_hub      # C3 全自动（含烧后自动校时）
python3 tools/flash_s3_auto.py _wb 1800   # S3：等按键 → 自动烧 → 自动抓日志

# 观察
mon 30               # 腕端串口
monc3 20             # 中枢串口
python3 tools/mon2.py --secs 30   # 两块板同时看
```

**腕端烧录必须人手按键**：S3 的原生 USB 被应用占用，esptool 无法自动复位进下载模式。
按住 BOOT → 短按 RST → 松 BOOT 进下载；烧完再按一次 RST 启动。

## 关键设计

| 决定 | 理由 |
|---|---|
| 测手腕而不是手指/额头 | 可长期佩戴、皮下血流稳定、对冷热响应明确 |
| ESP-NOW 而不是 WiFi+云 | 延迟 <10ms、无依赖、低功耗、隐私 |
| 红外而不是空调 API | 存量空调没有开放接口，但都有红外接收头，零改造 |
| 手环不联网校时 | 一联网信道就跟着 AP 变，ESP-NOW 立刻断；时间由中枢经下行包下发 |
| 慢闭环 60s / 单步 1℃ | 人体热惯性大，控太快等于追着噪声跑 |
| 不确定时冻结 | 断链或传感器故障时保持现状，而不是猜一个值继续调 |

## 目录结构

```
firmware/
  _wb/           ★ 腕端主力固件（M601 + 屏幕 + ESP-NOW 双向）
  _c3_hub/       ★ 中枢主力固件（DHT11 + 红外 + ESP-NOW + 对外 API）
  _m601/         M601 驱动验证
  _aux_send/     奥克斯红外帧构造与自检
  _ir_learn/     遥控器录码
  _ui/ _w1*/ _probe*/   历史中间版本
tools/
  c3mon.py       单板监听（不碰 DTR/RTS，不会复位板子）
  mon2.py        双板同时监听
  wait_boot.py   等 S3 启动后自动抓日志
  flash_s3_auto.py  一键：等按键 → 烧录 → 抓日志
docs/
  00-AI交接文档.md     硬件/协议/接口/流程图/任务清单
  01-学生参赛汇报稿.md  项目理念/方案/原理 + 学生实验设计
  archive/             早期方案（已被实测推翻，仅作历史留存）
env.sh           环境变量 + 编译烧录函数
```

`firmware/` 下除 6 个主力/验证 sketch 外，其余是排障过程中的探针固件（`_probe*`、`_w1*`、`_ds*` 等）。保留它们是因为**排障过程本身有答辩价值**：从"读数 −17.7℃"到定位出公式漏了 `+40`，中间那几十次试错都在这些文件里。

## 对外 API（中枢侧，给控制逻辑用）

```cpp
float getSkinTemp();       // 手腕皮温 ℃，断链 >8s 返回 NAN
float getRoomTemp();       // 室温 ℃（含校准偏移）
float getRoomHumidity();   // 相对湿度 %
bool  linkAlive();         // 手环是否在线
void  acSet(uint8_t t);    // 制冷 + 设定 t℃ + 立即发红外（16~30 限幅）
void  acPower(bool on);    // 开 / 关机
```

## 分工说明

硬件驱动、无线通信、UI、骨架代码由工程实现；**温控决策逻辑留给学生自己思考和实验标定**——阈值取多少、持续多久才动作、异常怎么判，这些没有标准答案，正是要他们用实验数据去回答的问题。
