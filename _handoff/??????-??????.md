## 2. 硬件事实表（AI 复述用，不要改）

### 2.1 手环主控：微雪 ESP32-S3-Touch-LCD-1.69

| 项 | 值 |
|---|---|
| 芯片 | ESP32-S3R8，双核 240MHz |
| Flash / PSRAM | 16MB Flash / **8MB PSRAM（OPI，八线）** |
| 屏幕 | 1.69" IPS 240×280，驱动 **ST7789V2**，4 线 SPI |
| 触摸 | CST816T，I2C 地址 `0x15` |
| 板载 | PCF85063 RTC(`0x51`)、QMI8658 IMU(`0x6B`)、蜂鸣器、电池充电 |

**已固定引脚（禁止改，改了要同步改 TFT 配置）：**

```
LCD : DC=4  CS=5  CLK=6  DIN=7  RST=8  BL=15
I2C : SCL=10 SDA=11   （触摸 0x15 / RTC 0x51 / IMU 0x6B / MAX30205 0x48）
蜂鸣器: 42      电池采样: 1
```

> ⚠️ 板子只引出 4 个空闲 GPIO + 1 路 I2C + 1 路 UART。**MAX30205 必须挂 I2C（0x48）**，不要再占 GPIO。

### 2.2 红外节点：ESP32-C3

```
红外发射（经 8050 三极管）: GPIO3   （2 颗以上 LED 必须三极管驱动，理由见方案文档 §5）
红外接收（学码时用）      : GPIO4
```

### 2.3 接线速查（写代码前核对）

- MAX30205：`VCC→3V3`（**绝对不能 5V**）、`GND`、`SDA→GPIO11`、`SCL→GPIO10`，其余脚悬空
- 红外 LED：`3V3 → 100Ω → LED 正极 → LED 负极 → 三极管 C`；`E→GND`；`B → 1kΩ → GPIO3`
- 学码接收头 VS1838B：`VCC→3V3`、`GND`、`OUT→GPIO4`

## 3. T0.1 装工具链

### 目标
机器上 `arduino-cli` 可用，`esp32` 内核装好，项目能编译通过一个空 sketch。

### 为什么用 arduino-cli 而不是 IDE 装包
AI 能直接执行命令、读日志、判断结果。GUI 装包失败时 AI 看不见原因。**IDE 只作为备选**（T0.1-B）。

### 步骤（AI 逐条执行，每条都要看到成功输出）

```bat
:: 1) 下载 arduino-cli 到固定位置（约 20MB）
::    官方地址：https://downloads.arduino.cc/arduino-cli/arduino-cli_latest_Windows_64bit.zip
::    解压到 C:\tools\arduino-cli\ ，把该目录加入 PATH
C:\tools\arduino-cli\arduino-cli.exe version

:: 2) 初始化配置
C:\tools\arduino-cli\arduino-cli.exe config init --overwrite
C:\tools\arduino-cli\arduino-cli.exe config add board_manager.additional_urls https://espressif.github.io/arduino-esp32/package_esp32_index.json

:: 3) 更新索引 + 装 ESP32 内核（约 1.3GB，要等 10~20 分钟）
C:\tools\arduino-cli\arduino-cli.exe core update-index
C:\tools\arduino-cli\arduino-cli.exe core install esp32:esp32

:: 4) 装库（一次装齐，后面阶段都要用）
C:\tools\arduino-cli\arduino-cli.exe lib install "TFT_eSPI"
C:\tools\arduino-cli\arduino-cli.exe lib install "IRremoteESP8266"
C:\tools\arduino-cli\arduino-cli.exe lib install "Adafruit MAX30205 Library"
C:\tools\arduino-cli\arduino-cli.exe lib install "ArduinoJson"

:: 5) 验证
C:\tools\arduino-cli\arduino-cli.exe core list
C:\tools\arduino-cli\arduino-cli.exe lib list
```

### 关键判断
- `core list` 里出现 `esp32:esp32  3.x.x  ...  installed` → 成功
- 若 `Adafruit MAX30205 Library` 搜不到，执行 `lib search max30205` 看实际包名，换名字再装
- 若 `config add` 提示已有 URL，忽略即可

### 验收标准
```bat
C:\tools\arduino-cli\arduino-cli.exe compile --fqbn esp32:esp32:esp32s3 C:\path\to\empty_sketch
```
输出含 `Sketch uses ... bytes` → **T0.1 通过**。

### T0.1-B 备选：Arduino IDE 2.x
若学生坚持用 IDE：装 IDE → 首选项「附加开发板管理器网址」填 `https://espressif.github.io/arduino-esp32/package_esp32_index.json` → 开发板管理器搜 `esp32` 装 `esp32 by Espressif Systems` → 库管理器逐个装上面 4 个库。

## 4. T0.2 确认能烧、串口能打印（最关键的一关）

### 目标
一块只做 `Serial.println` + LED 闪烁的最小固件，能烧进去，串口能看到启动横幅。

### 4.1 先确认 USB 类型（决定后面所有参数）

让学生插上板子，AI 执行：

```bat
C:\tools\arduino-cli\arduino-cli.exe board list
```

同时让学生看设备管理器，按结果走两条路：

| 设备管理器显示 | 含义 | 后续参数 |
|---|---|---|
| `USB 串行设备 (COMx)` / `USB JTAG/serial debug unit` | **原生 USB**（S3 内置） | `CDCOnBoot=cdc`，`UploadMode=default` |
| `Silicon Labs CP210x (COMx)` | 外置 UART 桥 | `CDCOnBoot=disabled` |
| `wch.cn CH343 (COMx)` | 外置 UART 桥（微雪常用） | `CDCOnBoot=disabled` |

- **驱动没装**（设备管理器里有黄色感叹号）→ 按芯片找驱动：CP210x 去 Silicon Labs 官网，CH343 去 WCH 官网（`wch.cn`），装完重插。
- **看不到任何 COM 口** → 90% 是**充电线**（只有电源线芯）。换一根能传数据的线，这是最高频的坑。

### 4.2 把板子参数固定成一个 FQBN 宏

在 `firmware/` 下建 `build_env.bat`，**所有编译烧录都调它**，避免每次手打参数出错：

```bat
@echo off
set CLI=C:\tools\arduino-cli\arduino-cli.exe
set FQBN=esp32:esp32:esp32s3:USBMode=default,CDCOnBoot=cdc,UploadMode=default,CPUFreq=240,FlashMode=qio,FlashSize=16M,PartitionScheme=app3M_fat9M_16MB,PSRAM=opi,LoopCore=1,EventsCore=1,DebugLevel=none
set PORT=COM__FILL_ME__
```

**参数说明（为什么这么设）：**

| 参数 | 值 | 原因 |
|---|---|---|
| `PSRAM=opi` | 必填 | 板子是 **S3R8 = 八线 PSRAM**。设成 `qspi` 会启动即崩、无限重启。**这是本板第一大坑** |
| `FlashSize=16M` | 必填 | 实际 16MB，默认 4MB 会导致分区表不匹配 |
| `PartitionScheme=app3M_fat9M_16MB` | 推荐 | 程序区 3MB，够 TFT + WiFi + JSON 一起编 |
| `CDCOnBoot=cdc` | 视 USB 类型 | 原生 USB 必须开，否则 `Serial` 无输出（屏幕黑、串口空，最容易误判为板子坏） |
| `FlashMode=dio` | **实测必须 dio** | 2026-11-11 实测：烧成 `qio` 后芯片无限重启（`rst:0x7 TG0WDT_SYS_RST`，ROM 加载完 bootloader 就挂）。本板原始固件镜像头也是 DIO。**不要用 esptool 的 `--flash-mode qio` 覆盖镜像头** |

### 4.3 最小验证固件

```cpp
// firmware/_smoke/_smoke.ino
void setup() {
  Serial.begin(115200);
  delay(1500);                       // 等 USB 枚举，别删
```

### 4.4 烧录命令

```bat

%CLI% compile --fqbn %FQBN% --output-dir firmware\_smoke\build firmware\_smoke
%CLI% upload -p %PORT% --fqbn %FQBN% --input-dir firmware\_smoke\build
```

1. 烧录日志出现 `Hash of data verified` 或 `Hard resetting via RTS pin`
2. 串口出现 `=== BOOT OK ===`
3. **`psram=8MB`**（如果打印 0MB 或 2MB → PSRAM 参数错或板子型号不对，必须停下来查）

## 6. T1.x 传感器与显示（第一周交付）

### T1.1 MAX30205 读温度

**I2C 扫描先行**（必做，否则接线错了也看不出来）：

```cpp
// 扫到 0x48 才算接线正确；顺便看 0x15/0x51/0x6B 是否都在
#include <Wire.h>
void setup(){ Serial.begin(115200); Wire.begin(11,10); }
void loop(){
  for(uint8_t a=1;a<127;a++){
    Wire.beginTransmission(a);
    if(Wire.endTransmission()==0) Serial.printf("found 0x%02X\n", a);
  }
  delay(3000);
}
```

**读温度（两种写法，按库的实际 API 二选一）：**
- 用 Adafruit 库：`Adafruit_MAX30205 sensor; sensor.begin(&Wire); sensor.readTemperature();`
- 库 API 不符时，**手写寄存器读**（更可靠，MAX30205 只用 3 个寄存器）：

```cpp
// 地址 0x48；reg 0x00 = 温度（16bit，高字节在前，1 LSB = 0.00390625°C）
float readTempC() {
  Wire.beginTransmission(0x48);
  Wire.write(0x00);
  Wire.endTransmission(false);
  Wire.requestFrom(0x48, 2);
  if (Wire.available() < 2) return NAN;
  uint16_t raw = (Wire.read() << 8) | Wire.read();
  return (int16_t)raw * 0.00390625f;
}
```

**验收标准：**
- 串口每 2 秒打印一次温度，**手指捏住传感器时数值上升、松开后缓慢下降**
- 静置 5 分钟，读数跳动 **≤ ±0.2°C**（跳动更大 → 接线松动或供电噪声，先查线）
- 室温 20~28°C 之间（贴皮肤应该是 32~35°C，**不是 37°C，这点必须跟学生讲清楚**）

## 7. T2.x / T3.x / T4.x 任务定义

### T2.1 趋势算法（**参数固定，不要自己发明**）

```cpp
// config.h —— 参数全部集中，方便答辩时解释
#define SAMPLE_MS        30000   // 采样周期 30s
#define WINDOW_POINTS    60      // 窗口 60 点 = 30 分钟
#define TREND_THRESHOLD  0.05f   // °C/min，超过才算有趋势
#define CONFIRM_COUNT    3       // 连续 3 次才动作（防抖）
#define BASELINE_SKIP_MS 600000  // 前 10 分钟不算基线（热平衡期）
```

判定逻辑：
1. 每 30s 采样一次，压入环形缓冲（60 点）
2. 缓冲满 10 点后，做一次最小二乘拟合，得到斜率 `°C/min`
3. `slope < -0.05` 且 `当前值 < 基线` → `COLD`
4. `slope > +0.05` 且 `当前值 > 基线` → `HOT`
5. 否则 `STABLE`
6. 同一结论**连续 3 个周期**才真正下发指令，否则清零重计

**验收标准：** 串口输出 `[trend] skin=33.4 slope=-0.061 state=COLD confirm=2/3`，捏手/吹气能让 state 变化，**不乱跳**（10 分钟内 state 切换 ≤ 3 次）。

### T2.2 WiFi 上报（数据契约，两端必须一致）

```json
POST http://<网关IP>/api/report
Content-Type: application/json

{
  "ts": 1762690000,
  "skin": 33.4,
  "ambient": 24.1,
  "slope": -0.06,
  "state": "COLD",
  "confirm": 3
}
```

- 网关返回 `{"ok":true,"cmd":"temp_up"}` 表示收到并已执行
- 手环**不判断该发什么红外码**，只上报状态；由网关决定 → 职责单一，后续换空调只改网关
- WiFi 断开时本地缓存最近 10 条，重连后补发（不要丢数据）

**验收标准：** 用浏览器/curl 访问网关，能看到手环的数据在更新（间隔约 30s）。

### T3.1 红外学码（**必须实测，禁止抄网上码值**）

```cpp
// 烧到 ESP32-C3：IRrecvDumpV2 示例，接收头 OUT→GPIO4
// 学生操作：拿自家空调遥控器，对准接收头按「制冷 26°C」
// 串口打印出 rawData 数组 + 一串十六进制
```

**产出**：一个 `ir_codes.h`，里面是学到的码：
```cpp
// 格力 KFR-xx，制冷26度，实测采集
const uint16_t kRawCool26[] = { 9024, 4498, 570, 566, ... };
```
> 同一按键按 3 次，码值完全一致才算采准；不一致就是没对准或距离太远。

### T3.2 红外发射
用 `IRsend` + `sendRaw()` 回放数组。**先验证 LED 亮**：手机摄像头对着 LED，发射时能看到紫白色闪点。

**验收标准：** 站 3 米外正对空调，按一次发送，空调有反应（滴一声/风叶动/显示屏变化）。

### T3.3 网关 HTTP + 指令映射

网关（C3）跑一个极简 HTTP server，路由 `POST /api/report`：
```
state=COLD 且 confirm>=3 → sendRaw(kRawTempUp)
state=HOT  且 confirm>=3 → sendRaw(kRawTempDown)
两分钟内不重复发同一条码（防连发）
```

**验收标准：** 手环捏热 → 30~90 秒后空调温度升 1 度，**全程没人碰遥控器**。

### T4.1 联调稳定性
- 连续运行 **2 小时**，记录重启次数（必须为 0）
- 拔掉 WiFi 再恢复 → 数据不丢、自动重连
- 手环断电重启 → 不需要人工干预能自己跑起来

### T4.2 演示脚本
3 分钟讲完，顺序固定：
1. 展示痛点（遥控器找不到）
2. 戴上手表，屏幕出现曲线（说明在测什么）
3. 用手捂热 / 吹冷 → 曲线变化 → 判定翻转
4. 空调自己动（这一下最有说服力）
5. 讲一句设计取舍：「红外必须对准，所以拆成手环 + 节点两个设备」

## 8. 烧录排障表（AI 按这个顺序查，不要自由发挥）

| # | 现象 / 报错 | 最可能原因 | 处理 |
|---|---|---|---|
| 1 | 设备管理器无 COM 口 | 充电线（无数据线芯） | **换线**。这是第一嫌疑，占一半以上 |
| 2 | 有 COM 口但带黄色 `!` | 驱动没装 | CP210x → Silicon Labs；CH343 → WCH 官网 |
| 3 | `Failed to connect to ESP32-S3: No serial data received` | 没进下载模式 | 按住 **BOOT** → 点一下 **RST** → 松开 BOOT → 重试 |
| 4 | 同上，且 BOOT 组合键无效 | 波特率太高 | 加 `--upload-speed 460800`，仍失败降 115200 |
| 5 | `Could not open port COMx` / `Access is denied` | 端口被占用 | 关掉串口监视器（`monitor` 进程）、关掉 IDE、关掉其它 AI 会话 |
| 6 | 烧录成功但串口**完全无输出** | `CDCOnBoot` 设错 | 原生 USB 必须 `CDCOnBoot=cdc`；外置桥必须 `disabled`，两种都试 |
| 7 | 烧进去就无限重启（Guru Meditation / `rst:0x3`） | **PSRAM 参数错** | 确认 `PSRAM=opi`。板子是 S3R8 八线 PSRAM，设 `qspi`/`disabled` 必崩 |
| 8 | `Sketch too big` | 分区方案太小 | `PartitionScheme=app3M_fat9M_16MB` |
| 9 | 编译报 `TFT_eSPI` 找不到 `User_Setup.h` | 库路径或选择宏错 | 用 §5.1 的绝对路径覆盖；确认 `User_Setup_Select.h` 里没 include 别的 setup |
| 10 | 屏白屏 / 全黑 / 花屏 | 引脚错、`TFT_HEIGHT` 错、背光没开 | 先确认 `TFT_BL=15` 且 `digitalWrite(TFT_BL, HIGH)`；再按 §5.1 的风险处置 |
| 11 | 屏幕花屏后重启（Brownout） | 供电不足 | 换主机后置 USB 口，**不要用 USB 扩展坞/前面板**；屏幕背光是大电流户 |
| 12 | WiFi 连不上 | 5GHz 不支持 / 中文 SSID | ESP32 只支持 **2.4GHz**；SSID 用英文，密码不含特殊符号 |
| 13 | 红外发不出去（摄像头看不到紫光） | LED 极性反 / 电阻过大 / 三极管 E-C 反 | 先直连 3V3+100Ω 测 LED（摄像头看紫光），再查三极管方向（平面朝自己，E-B-C） |
| 14 | 空调对码无反应 | 码没采准 / 距离太远 | 重采 3 次比对；拉到 2 米内直射；确认是 940nm 发射管 |

> 遇到表里没有的报错：**AI 先把完整报错原文贴进汇报**，不要自己编解释。
