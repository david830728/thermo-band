# 智能温控手环 —— 项目方案

> 一个能感知人体皮肤温度变化、并自动调节空调的穿戴设备。
> 本文档面向项目执行者（零基础可上手），按顺序读完就能开工。

---

## 一、项目要做什么

**一句话**：手环持续测量手腕皮肤温度，分析温度变化趋势，判断佩戴者是"感觉冷了"还是"感觉热了"，通过 WiFi 把指令发给红外节点，让空调自动调整。

**三个可独立验收的目标**：

1. 手环能把皮肤温度显示在屏幕上，并画出最近半小时的趋势曲线
2. 手环能根据温差判断冷热，给出"升温 / 降温"的建议
3. 空调能真的被手环控制（指令发出后，空调有响应）

---

## 二、系统组成

**为什么拆成两个设备？**

红外是**视线通信**，发射管必须对准空调的接收窗。手环戴在手腕上，抬手、翻身、走路，角度一直在变，发射成功率不可控。所以拆开：

```
┌─────────────────┐          ┌──────────────┐        ┌────────┐
│     手  环      │  WiFi    │   红外节点   │  红外  │  空调  │
│  （戴手腕上）   │ ───────→ │（固定在对面）│ ─────→ │        │
│                 │  指令     │              │ 38kHz  │        │
│ 测温·显示·判断  │          │ 只负责发射   │        │ 执行   │
└─────────────────┘          └──────────────┘        └────────┘
```

| 角色 | 负责 | 不负责 |
|---|---|---|
| **手环** | 测温、算趋势、判断冷热、显示、发指令 | 不发红外、不直连空调 |
| **红外节点** | 收到指令 → 发射对应红外码 | 不测温度、不做判断 |
| **空调** | 接收红外 → 执行 | 完全不知道温度数据的存在 |

## 四、温度传感器：怎么选、怎么用

### 4.1 先理解一件事：传感器测的是「它自己」

任何接触式温度传感器，测的都是**自己这一小块金属/硅片的温度**，不是"探测"你的体温。

它和你腋下夹的水银体温计一样：等几分钟，体温计升到和身体一样的温度，你读的是体温计自己的温度。

所以要让 MAX30205 测到皮温，关键是三件事：

| 要点 | 为什么 |
|---|---|
| **贴合要紧密** | 中间有空气层 = 测的是"皮肤和空气的平均值"，读数偏低 |
| **背面要隔热** | 芯片背面朝向空气，热量会散掉，必须垫泡棉 |
| **等热平衡** | 刚贴上去读数会一直往上爬，30 秒~2 分钟才稳 |

### 4.2 MAX30205 的装配方法（隔壳测温）

**芯片不需要碰到皮肤。** 智能手表都是这么做的——你摸到的是表壳，传感器藏在里面。

```
       空气
   ┌─────────┐
   │ 泡棉隔热 │  ← 挡住热量往上跑
   ├─────────┤
   │ PCB 模块 │
   │  [芯片]  │  ← 芯片朝下
   ├─────────┤
   │导热硅胶 │  ← 薄薄一层，赶走空气
   ├─────────┤
   │ 表壳0.8mm│  ← 正对芯片处做薄
   ├─────────┤
   │  皮肤    │  33°C
   └─────────┘
        ↑ 热流向上
```

**三个具体操作**：

1. 芯片面朝向表壳内侧，模块背面贴一小块泡棉
2. 表壳正对芯片的位置做薄到 **0.8mm 左右**（一般 3D 打印壁厚 1.2~1.6mm，局部改薄）
3. 芯片和表壳之间涂**一点点**导热硅胶，薄薄一层，别用厚胶垫（那反而是隔热层）

**⚠️ 排针不要焊直的**，会顶到屏幕。用弯针，或者干脆不焊，用细导线从焊盘引出。

### 4.3 接线（4 根）

| MAX30205 | 接到 ESP32-S3 |
|---|---|
| `VCC` | **3V3**（这颗芯片 2.7~3.3V，**绝对不能接 5V**） |
| `GND` | GND |
| `SDA` | **GPIO11** |
| `SCL` | **GPIO10** |

`OS`、`A0`、`A1`、`A2` **全部不用接**（悬空即默认地址 `0x48`）。模块上已经带了 4.7kΩ 上拉电阻，不用外加。

> I2C 总线上已经挂了三个设备：触摸（0x15）、IMU（0x6B）、RTC（0x51）。加上传感器的 0x48，**四个地址不冲突**，直接并联即可。

### 4.4 关于柔性温度传感器

市面上还有「柔性探头 + 串口模块」的方案。它的优点是**面接触**，贴手腕曲面比硬模块更服帖。

| | MAX30205 | 柔性串口模块 |
|---|---|---|
| 精度 | ±0.1°C | ±0.5°C 左右 |
| 占 GPIO | **0 个**（挂 I2C 总线） | 1~2 个 |
| 贴合手腕 | 靠表壳传热，需要设计 | **天生更贴合** |
| 接线难度 | 4 根线 + I2C 库 | 3 根线 + 读串口字符串 |
| 装配难度 | **要动脑**（凸台、导热胶） | 探头直接贴 |

**建议两个都买（多 30 元）**，先用柔性快速做出成果，再用 MAX30205 做精度对比——答辩时"为什么医疗级传感器值得多花心思"是个很好的论述点。

**如果买柔性模块，注意两点**：
- 优先用 **3V3 引脚供电**（用 5V 供电时，TXD 可能输出 5V 电平，会烧 ESP32 的引脚）
- 买回来先用串口助手确认**波特率**和**数据格式**，再写代码

## 五、空调怎么控制

### 5.1 为什么用红外，不用空调的 WiFi

很多同学会想："空调都有 WiFi，直接调它的 API 不就行了？"

实际情况是：

- 国产空调的 WiFi 基本只连厂商自己的云，**没有对外开放的局域网接口**
- 抓包逆向厂商协议，随时会因为 App 升级失效，不稳定
- 喜马拉雅那类平台的开放接口，**个人开发者根本申请不到**（只对企业开放）

**红外是唯一通用、稳定、零依赖的方案**：任何品牌任何型号的空调都吃红外码，不用联网、不用账号、不怕厂商改接口。

**WiFi 只用在我们自己两台设备之间**（手环 → 红外节点）。

### 5.2 红外方案怎么落地

**第一步：学码（必须做，不能抄）**

不同品牌、不同型号的空调红外码**都不一样**，网上抄来的十有八九不对。

1. VS1838B 接收头接 ESP32-C3（VCC→3V3、GND、OUT→任意 GPIO）
2. Arduino 里装 `IRremoteESP8266` 库，跑 `IRrecvDumpV2` 示例
3. 拿你家空调的原装遥控器，对着接收头按「制冷 26 度」
4. 串口会打印出一串十六进制——**记下来**

**第二步：发码**

装 `IRremoteESP8266` 库，如果是格力/美的/大金等主流品牌，库里通常有现成协议支持；如果没有，用学到的原始码直接回放。

### 5.3 红外发射电路（3 颗 LED）

```
ESP32-C3 GPIO ──1kΩ── [B  S8050]
                      [E]──── GND
                      [C]──── 三颗 LED 的负极
                              ↑每颗各自串 100Ω 到 3V3
```

**为什么不能直接接 GPIO**：3 颗并联需要 60mA，而 GPIO 最大只能输出 40mA，会烧引脚。

**为什么每颗都要串自己的电阻**：LED 参数有离散性，共用电阻会导致电流分配不均，亮的亮、暗的暗。

**E 和 C 别接反**：8050 平面朝自己、引脚朝下时，从左到右是 **E - B - C**。接反了不工作，但不会烧，对调再试。

### 5.4 验证发射管好坏的土办法

**红外光肉眼看不见**，但手机摄像头能看到——打开相机对着 LED，按发射时屏幕上会出现**紫白色闪点**。

这个技巧能省掉大量"到底是代码错还是硬件坏"的排查时间。

## 七、四周开发路线

**原则：每周都要有一个「能演示」的成果，不要一次做到最后才跑。**

### 第 1 周：让屏幕亮起来 + 读到温度

- [ ] 装 Arduino IDE，加 ESP32 开发板支持
- [ ] 烧微雪官方示例，确认**屏幕能显示、触摸有反应**
- [ ] MAX30205 接上 I2C，串口能打印出温度数值
- [ ] 把温度显示到屏幕上

**验收**：屏幕上显示一个大数字，手摸传感器数值会变。

### 第 2 周：画出趋势曲线

- [ ] 每 10 秒采一次温度，存进数组（保留最近 180 个点 = 30 分钟）
- [ ] 在屏幕上画出折线图
- [ ] 显示当前值和 30 分钟内的最大/最小值

**验收**：手握住传感器 1 分钟，屏幕上能看到一条明显上升的曲线。

### 第 3 周：判断冷热 + WiFi 上报

- [ ] 实现滑动窗口变化率计算（见第八节算法）
- [ ] 设定阈值，输出「偏冷 / 舒适 / 偏热」
- [ ] 手环连 WiFi，把判断结果发出去（先发到电脑上的一个测试页面即可）

**验收**：手环屏幕上能显示"偏热"，并且电脑上能收到这个状态。

### 第 4 周：红外控制空调

- [ ] 红外接收头学码，拿到你家空调的开机/关机/温度码
- [ ] 红外节点能独立发出这些码（先不联网，直接烧死测试）
- [ ] 手环发指令 → 节点收指令 → 发红外 → 空调响应
- [ ] 加防抖：连续 3 个周期都满足条件才动作

**验收**：手环上点一下"降温"，空调温度真的降了 1 度。

## 八、算法思路（不用搞复杂）

```
1. 采样：每 30 秒一次，存最近 60 个点（30 分钟）
2. 基线：佩戴稳定 10 分钟后，取平均值作为"我的正常温度"
3. 趋势：对最近 10 个点做线性回归，算出每分钟变化率
4. 判断：
     变化率 < -0.05°C/min 且 低于基线 → 偏冷
     变化率 > +0.05°C/min 且 高于基线 → 偏热
     否则 → 舒适
5. 防抖：连续 3 个周期（约 1.5 分钟）都是同一结论，才真正发指令
```

**为什么一定要有基线**：每个人的手腕皮温基线差 1~2°C，冬天夏天也差很多。**只看绝对值一定会误判。**

**为什么一定要防抖**：手刚洗过、刚脱外套、伸进被窝，皮温都会骤变。没有防抖，空调会被搞得来回抽风。

## 九、必须知道的 8 个坑

| # | 坑 | 说明 |
|---|---|---|
| 1 | **手腕皮温是 32~35°C，不是 37°C** | 37 是核心体温。测出 33°C 是正常的，别以为坏了 |
| 2 | **只看皮温会误判** | 建议加个环境温湿度传感器（BME280，十几块），用「皮温 - 环境温度」判断更准 |
| 3 | **红外码必须实测** | 不同型号不一样，抄网上的十有八九不对，**必须用接收头学** |
| 4 | **GPIO 不能直驱 3 颗红外 LED** | 60mA > 40mA 上限，必须加三极管 |
| 5 | **100Ω 电阻不能省** | 500Ω 只能给 4mA，红外 LED 基本不发光，遥控距离不到 1 米 |
| 6 | **MAX30205 不能接 5V** | 芯片供电 2.7~3.3V，接 5V 直接烧 |
| 7 | **电池必须带保护板** | 没有保护板的锂电过放会鼓包、起火 |
| 8 | **触摸屏驱动是最容易卡的地方** | 先用微雪官方例程跑通，别自己从头配 TFT_eSPI |

## 十、答辩怎么讲

**推荐顺序（讲的是思考过程，不是零件清单）**：

1. **痛点**：空调遥控器永远找不到；温度调多少全靠猜，不是冷就是热
2. **思路**：让机器感知人的真实状态，而不是让人去适应机器
3. **难点与解决**：
   - 皮温 ≠ 体温 → 用基线 + 相对变化，不看绝对值
   - 红外必须对准 → 拆成手环 + 固定节点
   - 数据会抖动 → 加防抖，连续 3 次才动作
4. **演示**：屏幕上的趋势曲线 → 点"降温" → 空调真的响了
5. **局限与改进**：单点皮温代表性有限，未来可加环境温度、心率辅助判断

**评委会问的两个问题，提前准备好答案**：

- *"为什么不用空调自带的 WiFi？"* → 厂商云不开放，逆向不稳定；红外通用、离线可用
- *"凭什么说人冷了？"* → 不是绝对温度，是相对自己基线的变化率，且要求持续一段时间
