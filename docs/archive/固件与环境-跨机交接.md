## 1. macOS 环境搭建

### 1.1 装 arduino-cli

```bash
# 方式 A：Homebrew（推荐）
brew install arduino-cli

# 方式 B：官方二进制（没装 brew 时）
curl -fsSL https://raw.githubusercontent.com/arduino/arduino-cli/master/install.sh | sh
# 装到 ./bin/arduino-cli，建议 mv 到 /usr/local/bin/ 或 ~/bin/

arduino-cli version      # 期望 1.x（Windows 那边是 1.6.0，1.0+ 都行）
```

### 1.2 装 ESP32 内核（**锁 3.3.12**）

```bash
arduino-cli config init
arduino-cli config add board_manager.additional_urls https://espressif.github.io/arduino-esp32/package_esp32_index.json
arduino-cli core update-index
arduino-cli core install esp32:esp32@3.3.12
arduino-cli core list        # 应显示 esp32:esp32 3.3.12 installed
```

> **为什么要锁版本**：3.3.12 是昨天所有验证（PSRAM、SPI、串口）跑通的那一版。换版本可能引入新的编译/运行时差异，调试期不要变。

macOS 的内核和库装在 `~/Library/Arduino15/`（对应 Windows 的 `%LOCALAPPDATA%\Arduino15`）。

### 1.3 可选库（**只有用到旧版固件才需要装**）

主固件（`_ui` / `_wave` / `_ds` / `_ds2` / `_hunt` / `_raw`）**不需要任何外部库**。

只有跑 `_sensors`（用 OneWire/DallasTemperature 那版）才需要：

```bash
arduino-cli lib install "OneWire" "DallasTemperature"
```

⚠️ **不要装 TFT_eSPI**，也不要装 Arduino_GFX —— 前者在这块板上 `tft.init()` 必崩，后者编译极慢。

## 2. 连接与端口

```bash
arduino-cli board list
# 或者
ls /dev/cu.*
```

插上板子后会出现一个设备，形如：

```
/dev/cu.usbmodem1101      ← 原生 USB（ESP32-S3 内置 USB-Serial/JTAG）
```

> - 用 `cu.*` 不要用 `tty.*`（tty 会被系统抢占等 DCD 信号）
> - macOS 上**通常只有一个**设备名（Windows 上分应用模式 COM25 / 下载模式 COM26 两个，Mac 一般不会换名，但下载模式和运行模式的设备号仍可能变，插拔后重新 `ls` 一下）
> - 如果 `/dev/cu.usbmodem*` 不存在：换一根**能传数据**的 Type-C 线（充电线是头号坑）

## 3. 编译与烧录

### 3.1 FQBN（**逐字照抄，改一个字都可能起不来**）

```bash
export FQBN="esp32:esp32:esp32s3:USBMode=default,CDCOnBoot=cdc,UploadMode=default,CPUFreq=240,FlashMode=dio,FlashSize=16M,PartitionScheme=app3M_fat9M_16MB,PSRAM=opi,LoopCore=1,EventsCore=1,DebugLevel=none"
export PORT=/dev/cu.usbmodem1101
```

**每个参数为什么这么设：**

| 参数 | 值 | 原因 |
|---|---|---|
| `FlashMode=dio` | **必须** | 设成 `qio` 会**无限重启**（`rst:0x7 TG0WDT_SYS_RST`）。昨天实测过，也对比过原厂固件镜像头确实是 DIO |
| `PSRAM=opi` | **必须** | 本板是 S3R8 八线 PSRAM，设 `qspi` 必崩 |
| `FlashSize=16M` | 必须 | 实际 16MB |
| `PartitionScheme=app3M_fat9M_16MB` | 必须 | 程序区 3MB，与出厂一致 |
| `CDCOnBoot=cdc` | 必须 | 原生 USB 不设这个，串口没输出 |
| `CPUFreq=240` / `LoopCore=1` / `EventsCore=1` | 默认 | 与出厂一致 |

### 3.2 最省事的一条命令（编译 + 烧录）

```bash
cd <工作区路径>/智能温控手环
arduino-cli upload -p $PORT --fqbn "$FQBN" firmware/_ui
```

### 3.3 只想编译（不插板子）

```bash
arduino-cli compile --fqbn "$FQBN" --output-dir build/_ui firmware/_ui
# 成功标志：Sketch uses 396240 bytes (12%) of program storage space
```

### 3.4 烧录失败时的兜底：直接用 esptool

```bash
ESPTOOL=$(ls ~/Library/Arduino15/packages/esp32/tools/esptool_py/*/esptool | head -1)
CORE=~/Library/Arduino15/packages/esp32/hardware/esp32/3.3.12

$ESPTOOL --port $PORT write-flash \
  0x0     build/_ui/_ui.ino.bootloader.bin \
  0x8000  build/_ui/_ui.ino.partitions.bin \
  0xe000  "$CORE/tools/partitions/boot_app0.bin" \
  0x10000 build/_ui/_ui.ino.bin
```

> ⚠️ **绝对不要**加 `--flash-mode qio` / `--flash-size 16MB` 这类覆盖参数 —— 会改写镜像头，导致 boot loop。让 esptool 用文件自带的头部。

### 3.5 看串口

```bash
# 方式 A：arduino-cli（推荐，Ctrl+C 退出）
arduino-cli monitor -p $PORT -c baudrate=115200

# 方式 B：screen（退出：Ctrl+A 然后按 K，再按 Y）
screen $PORT 115200

# 方式 C：Python（昨天全程用这个，最可控）
python3 -c "
import serial,time
s=serial.Serial('$PORT',115200,timeout=0.3)
t=time.time()
while time.time()-t<20:
    print(s.read(4096).decode('utf-8','replace'),end='')
"
```

**烧录前必须先退出 monitor / screen**，否则报端口占用。

## 5. 硬件参数速查（改代码必须核对）

### 5.1 引脚

```
LCD : DC=4  CS=5  CLK=6  DIN=7  RST=8  BL=15
I2C : SCL=10 SDA=11   （触摸 0x15 / RTC 0x51 / IMU 0x6B / 外部 MAX30205 应为 0x48）
蜂鸣器: 42          电池采样: 1
扩展口: 5V / 3V3 / GND / SCL(GPIO10) / SDA(GPIO11) / TX(43) / RX(44) / GPIO2 / GPIO3 / GPIO17 / GPIO18
```

### 5.2 ST7789 手写驱动关键参数

| 项 | 值 | 说明 |
|---|---|---|
| SPI | `SPI.begin(6, -1, 7, 5)`，`SPISettings(40000000, MSBFIRST, SPI_MODE0)` | SCK=6, MISO 不用, MOSI=7, CS=5 |
| MADCTL (0x36) | **`0x00`** | 方向是对的（照片里"画面转了"是拍摄角度问题） |
| **Y 偏移** | **窗口 y 加 20** | 240×280 面板显存是 240×320，可视区从第 20 行开始。**漏了会出现一条彩色噪点带** |
| COLMOD (0x3A) | `0x55` | RGB565 |
| 初始化序列 | SWRESET → SLPOUT → COLMOD → PORCTRL → GCTRL → VCOMS(0x19) → LCMCTRL → VDCVRHEN → VRHS → VDVS → FRCTRL2 → PWCTRL1 → 两组 GAMMA → INVON → NORON → DISPON | 完整代码见 `firmware/_ui/_ui.ino` |

### 5.3 传感器接线（已确认正确）

| 传感器 | 接法 |
|---|---|
| **DS18B20**（金属壳探头） | `VCC → 3V3`、`GND → GND`、`DO(DQ) → GPIO17`，**DO 与 VCC 之间跨 4.7kΩ 上拉** |
| **MAX30205** | `VCC → 3V3`（**绝对不能 5V**）、`GND`、`SDA → GPIO11`、`SCL → GPIO10`，A0/A1/A2 悬空（地址 0x48） |

> 板子的扩展口**出厂没焊排针**，目前是直接焊线在焊盘上。

## 6. 昨天踩过的坑（Mac 上会不一样的已标注）

| # | 坑 | 说明 |
|---|---|---|
| 1 | **FlashMode 用 qio → 无限重启** | 必须 `dio`。症状：串口每 2.5s 重复 `rst:0x7 (TG0WDT_SYS_RST)` |
| 2 | **TFT_eSPI 的 `tft.init()` 直接 PANIC** | 全白屏 + 背光亮 + 静默重启。`esp_reset_reason()` 返回 `4`。改用**手写驱动**，别修这个库 |
| 3 | **Arduino_GFX 编译慢到不可用** | 库 327 个文件，arduino-cli 给每个产物单独起 shell 进程复制；工程在 USB 机械盘上更慢。**Mac 上会快很多，但仍不推荐** |
| 4 | **软复位不可靠**（⚠️ **Windows 特有**） | Windows 的 usbser 驱动不传 DTR/RTS → `--after hard-reset` 假复位，每次必须手动按 BOOT+RST。**macOS/Linux 上通常正常，先试自动复位** |
| 5 | 端口会换号（Windows） | 应用模式 COM25 / 下载模式 COM26。Mac 上重新 `ls /dev/cu.*` |
| 6 | 读串口收不到数据（Windows） | pyserial 打开时必须 `dtr=True, rts=False`，否则 HWCDC 丢弃输出。Mac 上 `screen`/`monitor` 默认就正常 |
| 7 | 手动进下载模式 | 按住 **BOOT** → 点一下 **RESET** → 松开 BOOT |
| 8 | 出下载模式 | 只按一下 **RESET** |

## 7. 当前进度与昨天的结论

### 已完成 ✅

| 项 | 证据 |
|---|---|
| T0.1 工具链 | arduino-cli 1.6.0 + esp32 3.3.12 装齐，编译通过 |
| T0.2 烧录 + PSRAM | `chip=ESP32-S3 cores=2 rev=2` / `flash=16MB` / **`psram=8MB`** / `sdk=v5.5.5`，连续跑 20 分钟不重启 |
| T0.3 点屏 | 红/绿/蓝满屏 + 白边框 + 文字全部正常（手写驱动） |
| I2C 总线 | 板载 `0x15`(触摸) `0x51`(RTC) `0x6B`(IMU) `0x7E` 全部应答 |

### 未完成 ❌

**MAX30205（0x48）和 DS18B20 都读不到数据。** 已经排除的原因：

| 怀疑点 | 排除依据 |
|---|---|
| 固件/引脚选错 | `_allscan` 扫了 6 个 1-Wire 引脚 + 8 组 I2C 引脚对 |
| SDA/SCL 接反 | `_hunt` 用反序扫描（SDA=10/SCL=11），结果 B=0 |
| 地址偏移（A0/A1/A2） | 全地址 1~126 扫描，`i2c` 计数始终 4，没有新设备 |
| 上拉电阻缺失 | 加了 4.7k 前后数据完全一致 |
| 采样时序 | `_ds2` 扫了 32 组组合，ROM 读数全是 FF |
| 供电（3V3） | 学生确认黄线在 3V3、棕线在 GND，4 根线焊接牢固 |
| 总线本身 | 板载三个 I2C 器件工作正常 |

**DS18B20 的诡异表现（`_wave` 抓的）：**

```
A reset480 release    start=1   [end=1]               ← 480µs 复位后无任何反应
B reset1000 release   start=1  @107->0  @151->1       ← 1000µs 复位后 107µs 才拉低，只低 44µs
C slot after 0x33     start=0   [end=0]               ← 读槽把线摁低 70µs 不放开
D slot after 0xCC     start=1   [end=1]               ← 同样读槽却一直是高
```

→ 同一根线、相邻两个读槽行为相反，**不是软件能造成的**，指向器件本体异常（兼容片或坏片）。

## 9. 附录：两个核心固件的完整源码（保险拷贝）

> 正式代码在 `firmware/` 目录，这里是防止文件没拷过去的兜底。**目录名和 .ino 文件名必须一致**（Arduino 要求）。

### 9.1 `_ui/_ui.ino` —— 手写 ST7789 仪表盘（主力固件）

见 `firmware/_ui/_ui.ino`（约 330 行）。要点：

- 5×7 点阵字体表（`kFont[]`），支持 `0-9 A B C D E G I K M N O P R S T U V X Y - . : ?`
- `setWindow()` 里对 y 加 `YOFF=20`
- `fillRect()` / `drawChar()` / `drawText()` 三层封装
- 传感器部分：`rescan()` 每 8 次循环（约 12s）重扫 I2C + 1-Wire
- 1-Wire 用**位操作 + 内部上拉**实现，不依赖 OneWire 库

### 9.2 `_wave/_wave.ino` —— 1-Wire 波形抓取（诊断神器）

```cpp
#include <Arduino.h>
#define PIN 17

static inline void owLow() { digitalWrite(PIN, LOW); pinMode(PIN, OUTPUT); }
static inline void owRel() { pinMode(PIN, INPUT_PULLUP); }

void trace(const char *tag, uint16_t totalUs) {
  uint8_t prev = digitalRead(PIN);
  uint32_t t0 = micros();
  Serial.printf("  %-22s start=%d", tag, prev);
  while (micros() - t0 < totalUs) {
    uint8_t now = digitalRead(PIN);
    if (now != prev) { Serial.printf("  @%lu->%d", (unsigned long)(micros() - t0), now); prev = now; }
  }
  Serial.printf("   [end=%d]\n", prev);
}

bool resetPulse(unsigned long lowUs) {
  owLow(); delayMicroseconds(lowUs); owRel();
  delayMicroseconds(70);
  bool p = (digitalRead(PIN) == LOW);
  delayMicroseconds(410);
  return p;
}
void writeBit(uint8_t b) {
  if (b) { owLow(); delayMicroseconds(6);  owRel(); delayMicroseconds(64); }
  else   { owLow(); delayMicroseconds(60); owRel(); delayMicroseconds(10); }
}
void writeByte(uint8_t v) { for (uint8_t i = 0; i < 8; i++) { writeBit(v & 1); v >>= 1; } }
uint8_t readBitSlot() {
  owLow(); delayMicroseconds(3); owRel(); delayMicroseconds(10);
  uint8_t b = (digitalRead(PIN) == HIGH) ? 1 : 0;
  delayMicroseconds(55);
  return b;
}

void setup() {
  Serial.begin(115200); delay(1500);
  Serial.println("\n=== 1-WIRE WAVE TRACER ===\n");
  pinMode(PIN, INPUT);        delay(5); Serial.printf("pin float     = %d\n", digitalRead(PIN));
  pinMode(PIN, INPUT_PULLUP); delay(5); Serial.printf("pin pullup    = %d\n", digitalRead(PIN));
  pinMode(PIN, INPUT_PULLDOWN); delay(5); Serial.printf("pin pulldown  = %d\n", digitalRead(PIN));
  pinMode(PIN, INPUT_PULLUP); delay(50);
}

void loop() {
  Serial.println("\n----------------------------");
  owLow(); delayMicroseconds(480); owRel();  trace("A reset480 release", 400);
  owLow(); delayMicroseconds(1000); owRel(); trace("B reset1000 release", 400);
  if (resetPulse(480)) {
    writeByte(0x33);
    owLow(); delayMicroseconds(3); owRel();
    trace("C slot after 0x33", 70);
    uint8_t rom[8];
    for (int i = 0; i < 8; i++) rom[i] = readBitSlot();
    Serial.print("  ROM:"); for (int i = 0; i < 8; i++) Serial.printf(" %02X", rom[i]); Serial.println();
  } else Serial.println("  C: no presence");
  if (resetPulse(480)) {
    writeByte(0xCC);
    owLow(); delayMicroseconds(3); owRel();
    trace("D slot after 0xCC", 70);
  } else Serial.println("  D: no presence");
  delay(3000);
}
```
